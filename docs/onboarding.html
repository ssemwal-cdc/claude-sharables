Approval Plugin Setup

Two plugins that review your NetSuite and Procore approval queues, check the figures against the attached support, and let you approve or reject from one dashboard.

Before you start

About 45 minutes, with a good place to stop after step 3. Stay around for the whole thing — it pauses to ask permission and won't go on without you. But most of that time is a download, an install and a restart, so a glance every few minutes is enough.

  • The Claude desktop app, signed in with your Compass account.
  • Google Chrome, plus a Claude browser extension you'll install in step 1. Having used Claude in a Chrome tab is not the same thing.
  • A Procore login, a NetSuite login, or both. Install only the plugins you need.
1

Install the Claude Chrome extension everyone

Step 1 · in your browser This is a Chrome extension you install. Not a website. It lets Claude click through Procore and NetSuite for you. Install it, sign in, then leave it alone.
Don't skip this because you've "used Claude in Chrome" before.

A claude.ai tab is not this. Nor is the desktop app. You need a browser extension that lets Claude operate Chrome — open tabs, read pages, click buttons.

How to be sure: look for the Claude icon in Chrome's toolbar, next to the address bar. No icon, not installed.

  1. Use Google Chrome. Not Edge, not Safari.
  2. Sign in to Chrome with your Compass profile — profile icon, top right. Everything below happens in that profile.
  3. Install the extension, still in that profile: Claude on the Chrome Web Store. Click the blue Add to Chrome and accept the permissions prompt. No button means you're already installed, or in the wrong profile.
  4. Click the extension and sign in again with your Compass login. These are two separate sign-ins.
  5. In that same profile, sign in to Procore and NetSuite.
Done whenThere's a Claude icon in Chrome's toolbar, clicking it shows you signed in, and Procore and NetSuite both load without asking you to log in again.
Steps 2–5 · in the Claude desktop app Chrome is set up. Switch to the Claude desktop app now — everything from here happens there. Chrome just needs to stay open and signed in. Claude drives it in the background while you work in the app.
2

NetSuite connector optional · skip unless you already have it

Already know about the NetSuite MCP connector? Make sure it's connected: in the Claude desktop app, click your profile at the bottom left, then Settings → Connectors.

Never heard of it? Skip to step 3. It's a separate thing from your normal NetSuite login — having one doesn't mean you have the other — and the review works fine without it.

Done whenIt shows connected, or you've skipped it.
You have it — two things to know

Approve from your normal account, not the connector's. That's whose name goes on the approval. Connecting can leave the browser session on the connector's account, where you'll see someone else's queue or no approve buttons.

Sessions expire every few days — for everyone, using it for anything, not just this. Reconnect under Settings → Connectors. A run says so once, near the top, then carries on through your browser; you lose only the purchase-order cross-check until you reconnect.

3

Install the plugins

  1. Click your profile at the bottom left, then Settings → Plugins.
  2. Click Add, then Add marketplace.
  3. Enter the repo: ssemwal-cdc/claude-sharables
  4. Check auto sync is ticked before adding. It's what keeps you on the current version.
  5. Add it. Both plugins appear in the list.
  6. Install the ones you need — netsuite-approval-review, procore-open-items-review, or both.
Done whenYour plugins appear in the installed list. Not showing up in a new chat? Restart your computer. Still nothing after that means the marketplace didn't add — remove it and add it again, checking auto sync is ticked.
Good place to stop. Setup is done and saved — your plugins stay installed. Pick step 4 up whenever you have 15–20 minutes; it's the one stretch that doesn't resume partway.
4

First run

Budget 15–20 minutes for this step, and don't leave it for hours. It pauses to ask permission and waits, so stay nearby and glance over every few minutes — a timeout means starting this step over.

  1. Create a new chat. Keep it open — step 5 continues in it.
  2. Switch the toggle below the prompt box from Chat to Cowork.
  3. Set the model to the newest Opus, High effort.
  4. Set permissions to Auto — it will most likely be on Manual. Not "skip all permissions": that mode is for throwaway containers, and this one is signed in to Procore and NetSuite with your approval authority.
  5. Pick a folder when it asks — choose your Downloads folder. It makes its own subfolder in there; nothing already in Downloads is touched.
  6. Type the command below and hit Enter — don't describe it in your own words.

NetSuite

Procore

It will ask permission to use each site — pick always, not just once. You'll see it about three times. Pick "just once" and you'll be asked again on nearly every action.
Done whenA dashboard appears in the conversation listing the items waiting on you. Red banner across the top? It got cut off in transit — your figures are fine; say so and it re-renders smaller.
Where your work is saved

Inside Downloads: a NetSuite Approval Checks folder, a Procore Open Items folder, or both. Each holds your review history, the ids you confirmed, and the dashboard.

Choose Downloads every time. It's how a scheduled run knows whether it already ran today. Somewhere else — or renaming these — and the next run asks the setup questions again.

Skipped the folder entirely? Then nothing is remembered between runs. You'll answer the setup questions every single time, and a scheduled run can't tell whether it already went today — so it may run twice. The dashboard's page layout is kept in that folder too, which means a run with nowhere to keep it can stop short of drawing the dashboard instead of showing you one. Pick Downloads once and none of this comes up.

5

Run it on a schedule

In that same chat from step 4, hit Copy on the block for the plugin you set up, then paste it in as one message. You don't need to read it.

Claude asks about timing, then gives you an Add to schedule button. Click it. Do this once per plugin you installed, and only after you have done step 4 for that plugin — a schedule on a plugin whose first run never happened will stop to ask you setup questions with nobody watching. Both plugins? Do it twice — one block, add its schedule, then the other.

A reasonable answer: first try 11am, retries 2pm and 4pm, weekdays only. Closed that chat already? Start a new Cowork chat, connect Downloads again, run the step 4 command once, then paste below.

The words in that daily headline.

Flagged means the numbers did not tie or the support did not back them — read it before you decide anything. Skipped (Procore only) means nothing was attached to review, so it has no verdict yet and no verdict has been guessed for it; it is not a rejection. You may also see a row marked gate unknown, which means the plugin could not establish that the item is genuinely yours to answer — those rows deliberately carry no response buttons, and there is a link on them to go sort that out in Procore instead.

It only runs while your computer is on and Chrome is open.

Laptop shut at 11am and nothing happens — it doesn't queue up and run later. That's what the retries are for: if 11am misses, 2pm catches it; if 11am succeeded, the later ones see the day is done and stop.

Using it day to day

With the schedule running, the dashboard is already waiting. You can also start a review any time with the command from step 4.

  1. Read it. Each item shows a verdict, the figures behind it, and a link to the record.
  2. Newest is at the top — most recent first on NetSuite, longest deadline first on Procore. Sort, filter or search if it's long: by amount, age, vendor or type. Both dashboards remember what you set.
  3. Step 1 — mark what you want to action. Nothing has left the page yet, and you can change your mind on any of them.
  4. Step 2 — press Execute. There's a button at the bottom of the queue, and a second in the header once you've marked anything. Either one puts the instruction into the chat.
  5. They run through your own browser session, one record at a time.
Marking an itemThe buttons you'll see
NetSuite Approve, With notes, or Reject.
Procore Whatever that item's workflow step offers — usually Approve or Yes, and Reject or Revise and Resubmit. No "With notes", and a negative response asks you for a reason.
Every approval says so. They carry the note Approved by Claude in the audit trail; type your own and yours is used instead, word for word. Rejection reasons are never filled in for you — it stops and asks.

If something goes wrong

A run stopped partway, or nothing was approved
What you seeWhat to do
It stopped after one item and reports a frozen tab or that a click didn't land It stops rather than guessing, and it will not click the same item twice. It reports each item it confirmed and each one it could not — read that list before doing anything. Items it could not confirm may or may not have gone through, so check those in the system rather than assuming, and never say “retry the batch” without looking first.
It says the session expired Chrome was closed, or you were signed out. Reopen it in your Compass profile, sign in, run again. It never logs in for you.
It says the connector session expired Different thing — the NetSuite connector, not your browser. Reconnect under Settings → Connectors. The review still works meanwhile; it just skips the purchase-order cross-check.
An empty queue when you expected items Say so. A failed query and a truly empty queue look identical from outside — it should re-check through the browser rather than trust the first answer.

These are the failures actually seen.

Three things that will confuse you
What you seeWhat it means
Settings → Plugins says Last updated weeks ago That column tracks a catalog file that rarely changes — it says nothing about your plugins. Your real version is the skill's first line; see Keeping it updated.
A new plugin appears in the catalog but you don't have it Auto-update only maintains plugins you already installed. New ones need installing once.
The dashboard looks out of date, or shows old buttons A dashboard is a snapshot, so an update changes nothing already on screen. Restart, then run the review again for a fresh one.

Keeping it updated

With auto sync on, there's nothing to run. Fixes apply on your next restart, so you have them the following morning.

Forcing an update now

Only if you need a fix immediately, or auto sync got switched off. It all happens in the app, where you installed.

  1. Click your profile at the bottom left, then Settings → Plugins.
  2. Click Browse, then the Personal tab.
  3. Next to Local uploads there's a claude-sharables chip — click the ⋯ (three dots) on it.
  4. Click Check for updates. While you're in that menu: Sync automatically should be on, and Synced commit is the release you're on.
  5. Restart — the computer, not just the app — then run the review again for a fresh dashboard.

Still on an old version after that? In that same ⋯ menu, Remove the marketplace — this uninstalls its plugins — then add it back (step 3) and reinstall. That always lands you on current.

Which version am I on?

Click your profile at the bottom left, then Settings → Plugins, then the plugin itself. The last sentence of its Description reads "Skill version N" with a date. The current number is the Version column of the plugin table on GitHub — a lower number, or no version mentioned at all, means you're stale: force an update as above. Or skip the clicking and just ask in a chat: "what skill version are you on?"

Ignore the Last updated date on those plugin screens — it tracks a catalog file that rarely changes, so an old date there says nothing about your plugins.

What it will never do
  • Approve or reject on its own judgement. A verdict is a recommendation, nothing more.
  • Act on "approve everything clear." It requires named documents and will ask which.
  • Click without re-checking. It confirms the number, vendor and amount on the record immediately before each click.
  • Keep going after a problem. If an item can't be confirmed, the whole batch stops.
The plugins update from ssemwal-cdc/claude-sharables; every push is a new version.
