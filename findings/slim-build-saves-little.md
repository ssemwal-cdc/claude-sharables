# The slim build saves little

**Superseded.** Read F‹slim-build-not-a-fallback›, slim build is no fallback. That record carries this measurement and the cost of a folded row.

**Outcome protected.** A reviewer keeps the response buttons a folded row would cost.

**Argument.**

Procore rendered the slim copy as its primary dashboard, justified as roughly a fifth smaller. That figure was wrong.

Only two verdicts fold, and a live queue is mostly neither. So the saving is small.

Procore now renders the full page like NetSuite. The slim copy is reached only when the integrity banner fires.

The slim copy is not a size fallback and never was.

**Evidence.**

- Measured 2026-08-24 across 5 fixture queue mixes. The real saving is 0% to 12%, and 2% to 6% on a realistic mix.
- At the large end 113 KB became 101 KB, which crosses no observed threshold.
- Measured again 2026-09-01 on a deliberately even 62-item fixture, 174 KB came down to 129 KB.
